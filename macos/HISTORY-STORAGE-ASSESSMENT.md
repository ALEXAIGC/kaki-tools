# 历史存储后续评估（未实施迁移）

当前历史格式和产品规则保持不变。普通、非固定、非分类、已完成的历史条目最多 100 条；固定项和分类中的独立副本不受该条数限制。图片处理中的条目暂不参与淘汰。文本主体没有单条字节限制，整个历史（含固定和分类）没有总字节上限；HTML/RTF 有现有单条边界，图片有现有像素、字节和处理队列预算。这些边界并不构成历史总容量限制。用户主动清空普通历史会包括固定项，分类副本仍保留。

本阶段只将自动保存的 JSON 编码和原子写入移到现有串行后台队列。主线程提取不可变值快照；队列按提交顺序保存。显式 flush/退出排空旧写入和图片任务，完成图片归档后同步保存最终快照，允许这一步阻塞以保证最后状态。pending 图片不写入索引。加载、完整迁移备份、损坏文件保护和只读模式沿用现有实现。没有文本外置、历史格式升级或新增自动删除规则。

## 后续外置方案

建议未来使用带明确版本的索引，保留条目 ID、排序、固定、分类、富文本关系和元数据，将大文本写入应用专属文件，并记录 UTF-8 字节数与完整性哈希。普通小文本可继续内联；阈值应由实际样本和用户选择确定，不能靠截断正文降低体积。读路径同时接受现有内联格式及新版本；路径只允许受管理目录内的安全相对路径。文本、RTF、HTML及分类副本之间的独立保留语义必须明确，任何共享文件都需可靠引用计数或等价引用扫描。

升级前制作可校验的完整备份：原历史、备用历史、图片及缩略图；若已存在外置文本，还必须包含文本文件和清单。迁移写入新文件及新索引到独立暂存区，逐条验证完整内容、哈希、引用与条目数量，最后原子提交索引。任一步失败保留原格式和原文件，不清理可能用于恢复的数据。备份文件需有一致的用户私有权限。迁移完成不立即移除原备份。

回滚必须同时恢复对应索引与全部负载文件。旧版本只理解内联文本时，回滚工具应从新文件重新构造完整旧格式；不能只换回一个旧索引却漏掉升级后新增内容。先导出及校验，再切换；空间不足或数据损坏则停止并保留所有原件。未来孤儿清理只能处理已证明不再被有效索引或保留备份引用的应用自有文件。

## 容量与验收

容量管理先提供准确统计和用户可审查的清理预览。默认保留固定及分类条目，正文不静默裁剪；总量或大条目规则须获得明确产品决定。不得把现有 100 条规则解释为可以自动删除全部固定/分类数据，也不应引入新的总字节上限而隐式改变保留行为。

未来验收至少覆盖：大 UTF-8/emoji 正文精确往返，RTF/HTML与纯文本关系，分类副本和固定保留，连续修改与退出顺序，图片/文本 pending 和删除并发，升级途中失败与空间不足，索引/负载损坏的只读保护，完整备份恢复，新旧格式混合读取，回滚包含升级后新数据。使用临时目录和合成内容，禁止直接迁移真实用户历史作为测试。

## 测试专用入口

当前测试脚本编译普通 Sources 并排除 Main，使用独立 TestMain；Main 仍有测试模式启动/截图等入口。本阶段不拆构建体系。后续如需区分生产与测试入口，应先清点环境变量、截图验收及自动化调用者，再提出独立小变更，保证生产 bundle ID、固定签名、资源与正常启动行为不变。
